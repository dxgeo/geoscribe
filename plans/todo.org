* Current Working Items
Live list of what's open right now — not the full historical plan index (see
[[file:README.org][README.org]] for that, ordered by dependency, everything
DONE included). Each entry is just a link to its real plan/section for detail;
check it off and remove it once the item ships or is shelved.

- [ ] [[file:wkt-identify.org::*OPEN QUESTIONS][wkt-identify.org — should =GCR1= carry a =deprecated= flag?]] —
  the highest-value follow-up from the identification work: 110 of 431
  geographic and 891 of 2,274 projected Esri =.prj= fixtures match *more than
  one* registry CRS equally well, almost always a deprecated ESRI code beside
  its live twin, and =identify_from_wkt= reports all of them rather than
  guessing. (Counts are post-2026-08-19, after the sphere and non-metre-axis
  fixes from [[file:projjson-identify.org][projjson-identify.org]] took both
  corpora to *zero unidentified* — which makes ambiguity the only residual
  failure mode left in all 2,705 real Esri rows, and this entry the last
  accuracy work outstanding.) =proj.db= has the column; the blob does not.
  Adding it is a =GCR1= v3 format change plus a regeneration, and carries a
  policy question of its own (preferring live over deprecated is a judgment —
  it belongs in =identify.rs=, not =resolve=).
- [ ] [[file:public-api.org::*MILESTONES][public-api.org — R6e, the acceptance test]] —
  confirm a consumer with *no* =geosetta= dependency can depend on =geoscribe=
  alone and resolve a real code. Vehicle changed 2026-08-18: =nazca='s path-dep
  and =geoscribe= feature were removed (no dependency edges between the three
  crates — see [[file:../../architecture.org][architecture.org]]), so use a
  throwaway smoke-test crate. /The other option it named -- a =dev-dependency=
  test on =nazca='s side over its =CrsRegistry= trait -- went away on
  2026-10-22, when reprojection moved here and =nazca= became a rendering
  library./ The plan flags this as the actual point of R6, not an
  afterthought.
- [ ] *How far does this crate's charter extend?* — "own whatever geospatial
  metadata isn't a simple pass-through" is an easy bar to satisfy sloppily, and
  envelope computation is now a worked example of it being satisfied *wrongly*:
  the capability read as in-charter, and was still in the wrong crate. The risk
  was never the first addition; it is that the next one gets less scrutiny.
  Tracked at [[file:../../architecture.org][architecture.org]] § OPEN QUESTIONS
  — no longer hosted in the retired plan
  ([[file:envelope-computation.org][envelope-computation.org]], RETIRED
  2026-08-18).

  /2026-10-22: the math half is answered./ *All* vector and raster math
  belongs here, whether or not it depends on the CRS (user decision;
  =../project.org= § CHARTER). The line drawn against =geosetta= is
  format encoding: values a format stores or needs in order to be written stay
  in =geosetta=. What is still open is the *metadata* half: "not a simple
  pass-through" has no falsifiable test yet.
- [ ] [[file:reprojection.org::*STATUS -- SCOPING ONLY, NOT YET IMPLEMENTED][reprojection.org — the five reopened points]] —
  the plan moved from =nazca= on 2026-10-22 and was written for a crate with
  no registry. Settle before R1: whether the =CrsRegistry= trait survives,
  whether =proj-db= ships, where Helmert and grid parameters come from (the
  embedded registry holds definitions only), raster warping's place, and
  vertical shift's priority now that KML has a consumer for it.
- [ ] [[file:reprojection.org::*MILESTONES][reprojection.org — R1–R7]] —
  =CrsDef= parsers (R1/R2), registry seam (R3/R4, see above), projection math
  and Helmert shift (R5/R6), and the =Crs=/=transform_to= seam (R7), which is
  what makes it usable. Oracle-checked against =cs2cs=/=ogr2ogr=.
- [ ] [[file:reprojection.org::*MILESTONES][reprojection.org — R8 and vertical shift]] —
  3D Helmert (R8), then the geoid-grid vertical shift deferred beyond it. The
  second has a consumer: KML altitudes are EGM96 heights
  ([[file:../../todo.org][../../todo.org]]; =geosetta/plans/kml-standard.org=
  D-K12).
- [ ] [[file:transform-bounds.org][transform-bounds.org]] — bbox
  transformation by edge densification, plus its three failure modes. Depends
  on R5/R7.
- [ ] *A CLI mode that reprojects piped geometry* — from =nazca='s old
  roadmap; see =../project.org= § ROADMAP. Not yet scoped.
- [ ] [[file:crs-registry.org::*RISKS / REMAINING OPEN QUESTIONS][crs-registry.org — table currency]] —
  the registry is only as current as the =proj.db= it was generated from; a
  newer EPSG release means regenerating the blob *and* re-checking attribution.
  No trigger for this exists today. A regeneration is also when
  [[file:wkt-identify.org::*OPEN QUESTIONS][wkt-identify.org's "does the
  ellipsoid-only bar hold as =proj.db= grows?"]] gets tested — rerun the bulk
  oracles, and add a real projection-parameter check only if one comes back
  *wrong* rather than merely declined.
- [ ] [[file:crs-registry.org::*RISKS / REMAINING OPEN QUESTIONS][crs-registry.org — snapping tolerance]] —
  exact vs. epsilon on parameter values in name/param-match validation; err
  toward *not* snapping. Governs recovery paths 2/3 only (inline ids are
  trusted).
